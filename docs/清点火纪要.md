# 清点火纪要（BUGFIX-08，当班封死）

- 生效：2026-11-23，当班封死；任何偏离本纪要的写法均记「清点火偏航」并拒写。
- 缺陷：开放超温游标请求未检查批次内残留超温点即报成功，监控台游标已开而曲线仍带尖峰。
- 根因：开户缺清点火。

## 口径（只走甲路，禁止第三路）

游标开户与清点火绑定，写路径只许择一，不得两边混用。本仓定稿：**甲路**。

1. 批次内仍有残留超温点（温度点 > 该游标阈值）→ 正式游标**零增**、**拒开**，批次游标态**零改**。
2. 残留点清零（点火清零）后才允许正式开放。
3. 禁止乙路「拟开 / 影子拟开」记录，也不做事后原子晋升；发现影子记录一律视为偏离纪要，相关状态不得报绿、不得被自动晋升。
4. 阈值取该批次最近一条正式游标的阈值；无游标时取仓间 `target_max + 2`。开户时可显式指定阈值。
5. 偏离纪要（含拟开影子、残留未清仍试图开户）记审计 `清点火偏航`，业务写入拒绝。

## 并发

- 同一批次开户须串行占**超温游标锁** `excursion:<batch_id>`（开户主锁）；同时仍占 `batch:<batch_id>`
  与封批写入互斥。
- 后到者只记争用痕迹（`contention_log`），不写业务。

## 五处同源（唯一出口 `backend/clearing.py`）

对账页、探头页、温谱页、批次页、游标页的「残留尖峰 / 游标态 / 一致性」一律取
`clearing.batch_state()` / `probe_state()` / `chamber_state()`，任何服务与页面不得自行判定。

- `spike_cleared = 残留超温点数为 0`
- `cursor_spike_consistent = spike_cleared and 无拟开影子记录`
- 出现「游标开放而曲线带尖峰」即为不一致，禁止报绿。

## 验收

- 三支失败测先红后绿：甲（残留仍开户）、乙（拟开影子报绿）、争用（双窗同批无锁双开）。
- 五处尖峰与游标判定一致（对账、探头、温谱、批次、游标）。
- 禁止只改超温视图色调；禁止无测合入后端；禁止跳过争用失败测。
